# FrameShot website

The marketing site for FrameShot is a set of static pages in [`website/`](website/), generated by the scripts in [`scripts/website/`](scripts/website/). There is no framework and no build step on the server: Vercel serves the folder as it is.

## Pages

| Address | Contents |
|---|---|
| `/` | Hero, features, an interactive tour, full-page capture, the screen recorder, a before/after redaction slider, why FrameShot, three steps, privacy, FAQ, guides and a closing call to action |
| `/blog` | All guides: the newest as a featured card, a topic filter (Guide, Recording, Tips, Workflow, Privacy), and every guide grouped by topic |
| `/blog/<slug>` | 16 guides: screenshots in Chrome, on a Chromebook, of part of a page, scrolling and full-page screenshots; screen recording on Windows, on a Mac with sound, in Chrome with audio, and tutorials with a webcam; annotating, blurring and redacting; saving pages as PDF or image; GIFs; choosing a recorder extension; privacy; bug reports |
| `/about` | What FrameShot is, how it is built, who makes it, contact |
| `/privacy` | The privacy policy, rendered from [`PRIVACY.md`](PRIVACY.md), plus a note about the website itself |
| `/support` | Free ways to help and the donation addresses (read from `src/core/donate.ts`) |
| `/coming-soon` | Where "Add to Chrome" goes until the store link is set (not indexed) |
| `404.html` | Not-found page |

Also generated: `sitemap.xml` (with image entries), `robots.txt`, `llms.txt` (a plain summary for AI assistants), `feed.xml` (RSS), `site.webmanifest`, social preview images in `og/`, favicons, and `vercel.json`.

## Deploy to Vercel

1. In Vercel, choose **Add New → Project** and import this GitHub repository.
2. Set **Root Directory** to `website`.
3. Set **Framework Preset** to **Other**, and leave the build command and output directory empty.
4. Click **Deploy**.

`website/vercel.json` turns on clean URLs (`/privacy` instead of `/privacy.html`), redirects `/chrome` to the install target, and sets security headers (a strict Content Security Policy, no framing, no camera or microphone access) and long-lived caching for files in `/assets`.

## Two settings to fill in

Both live at the top of [`scripts/website/config.mjs`](scripts/website/config.mjs). After changing either one, rebuild and commit:

```bash
npm run website
```

- **`SITE_URL`**: the address the site is served from. It is used in canonical links, the sitemap, the RSS feed and social previews, so it must match your real domain. It is set to `https://frameshot.uniquelabs.org`.
- **`STORE_URL`**: the Chrome Web Store listing, set to https://chromewebstore.google.com/detail/adcgjmghjagflmmndoajdidcopodacac. Every "Add to Chrome" button opens it, the structured data has an install link, the Support page shows a "Rate FrameShot" button, and `/chrome` and the old `/coming-soon` address redirect to it. (With no listing set, the buttons would lead to a coming-soon page instead.)

Both can also be passed for a one-off build:

```bash
SITE_URL=https://www.example.com STORE_URL=https://chromewebstore.google.com/detail/frameshot/ITEM_ID npm run website
```

The quickest way to point the buttons at the store, without a rebuild, is to change the `/chrome` redirect's `destination` in `website/vercel.json`. Rebuilding is still recommended so the structured data and the Rate button pick up the link.

## Commands

| Command | What it does |
|---|---|
| `npm run website` | Builds every page, the sitemap, the feed, the manifest and `vercel.json` |
| `npm run website:assets` | Re-creates the images, social previews and icons. Run it after `npm run store:assets` when the extension's UI changes |
| `npm run website:serve` | Serves `website/` at http://localhost:4173 with Vercel's clean URLs, redirects, headers and compression |
| `npm run website:check` | Opens every page in Chromium and fails on console errors, CSP violations, failed requests, images that don't load, broken internal links or anchors, invalid structured data, a missing or repeated `<h1>`, or images without alt text. It also saves screenshots in light and dark mode, for desktop and phone, to `.output/website-shots/` |

## Editing content

| What | Where |
|---|---|
| Site name, default title and description, developer details | `scripts/website/config.mjs` |
| Home page sections and the FAQ | `scripts/website/content/home.mjs` |
| Article titles, descriptions, tags, keywords and dates | `scripts/website/meta.mjs` (first six guides), `content/posts-a.mjs` and `content/posts-b.mjs` (`META_A`, `META_B`) |
| Article text | `scripts/website/content/posts.mjs`, `posts-a.mjs`, `posts-b.mjs` |
| Blog index, privacy, support, coming soon, 404 | `scripts/website/content/pages.mjs` |
| Styles (the extension's colours, light and dark) | `scripts/website/styles.css` |
| Interactions | `scripts/website/site.js` |

The visual system (white canvas, near-black ink, one emerald call-to-action colour, Inter 500 display type, 6 px buttons, 12 px hairline cards, no gradients) follows `docs/WEBSITE-DESIGN.md`; its tokens live at the top of `scripts/website/styles.css`.

Every product fact on the site matches the extension's code (see [FEATURES.md](FEATURES.md)). There are no ratings, user counts, reviews or testimonials; please keep it that way until real ones exist. Write in plain sentences rather than lists of keywords or file formats.

## Search optimisation

- Every page has a unique title (under about 62 characters) and description (110–160 characters); the build warns otherwise. Canonical links, Open Graph and Twitter cards, and a 1200×630 social image per page.
- Structured data on every page: Organization, Person (the developer) and WebSite; SoftwareApplication and FAQPage on the home page; BlogPosting (with keywords, section, word count and reading time), FAQPage (from each guide's "Common questions") and BreadcrumbList on guides; Blog, CollectionPage and ItemList on `/blog`; AboutPage on `/about`.
- Guides are written for one search each: the answer comes first, steps are numbered lists, comparisons are tables, and each ends with the questions people ask. Each links to related guides; "Keep reading" picks the three guides that share the most topics.
- `sitemap.xml` lists every indexed page with its last change and its images. `llms.txt` lists the pages and guides for AI assistants.
- To add a guide: add its metadata (with `keywords`) and body, run `npm run website:assets` (social image and card), then `npm run website` and `npm run website:check`.

## How it stays fast

- One HTML request per page: the CSS is inlined, and the only script (about 5 KB, 2 KB compressed, deferred) adds the interactions. All content is readable without it.
- Images are AVIF with a WebP fallback, in two sizes each, lazy-loaded below the fold, with width and height set so nothing jumps while loading. The hero screenshot is preloaded.
- One self-hosted variable font file, preloaded, with a size-matched fallback so text doesn't shift when it arrives.
- Animations move only `transform` and `opacity`, pause when off screen, and switch off when the system asks for reduced motion.
- File names in `/assets` carry a content hash, so browsers can cache them for a year and still pick up changes.

## After launch

- Add the site to Google Search Console and submit `https://<your-domain>/sitemap.xml`.
- Once the Chrome Web Store listing is live, set `STORE_URL` and rebuild.
- Add the website address to the store listing's "Official URL" and "Homepage URL" fields.
